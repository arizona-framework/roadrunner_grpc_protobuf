# roadrunner_grpc_protobuf

Protocol Buffers for [Roadrunner](https://github.com/arizona-framework/roadrunner)'s
gRPC, with modules generated by [gpb](https://github.com/tomas-abrahamsson/gpb).

Roadrunner serves gRPC through `roadrunner_grpc`, and leaves how messages
turn into bytes to a codec. `roadrunner_grpc_protobuf` is the codec for
Protocol Buffers: it builds a gRPC service from what a gpb module knows of
it, encodes and decodes the messages with that module, and gives the
module's `.proto` files to server reflection, so tools like `grpcurl` can
list, describe and call your services.

## Installation

Roadrunner's gRPC is on its main branch and not yet in a Hex release, so
for now both come from git. Add them to your `rebar.config`, with
`rebar3_gpb_plugin` to generate the gpb module from your `.proto` files:

```erlang
{deps, [
    {roadrunner, {git, "https://github.com/arizona-framework/roadrunner.git", {branch, "main"}}},
    {roadrunner_grpc_protobuf,
        {git, "https://github.com/arizona-framework/roadrunner_grpc_protobuf.git", {branch, "main"}}}
]}.

{plugins, [rebar3_gpb_plugin]}.
{gpb_opts, [
    {i, "proto"},
    {o_erl, "src"},
    {o_hrl, "include"},
    {module_name_suffix, "_pb"},
    maps,
    strings_as_binaries,
    descriptor
]}.
{provider_hooks, [{pre, [{compile, {protobuf, compile}}]}]}.
```

The modules gpb generates run on their own, so gpb is only needed to build
them. With the `maps` option messages are maps; without it they are
records. The `descriptor` option gives server reflection the `.proto`
files, and can be left out if you do not turn reflection on.

## Usage

For a `helloworld.proto` with:

```proto
package helloworld;

service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}
```

write the methods in a module of their own, one function per method named
after it in snake case (`SayHello` is `say_hello/2`):

```erlang
-module(greeter).
-export([say_hello/2]).

say_hello(#{name := Name}, Stream) ->
    {reply, #{message => <<"Hello ", Name/binary>>}, Stream}.
```

Then build the service with `roadrunner_grpc_protobuf:service/3` and put
`roadrunner_grpc_protobuf` in `codecs`:

```erlang
{ok, _} = roadrunner:start_listener(grpc, #{
    port => 50051,
    protocols => [http2],
    body_buffering => manual,
    routes => roadrunner_grpc:routes(#{
        services => [roadrunner_grpc_protobuf:service(helloworld_pb, ~"helloworld.Greeter", greeter)],
        codecs => [roadrunner_grpc_protobuf],
        reflection => true
    })
}).
```

`service/4` takes options to name the functions another way, or to answer
`UNIMPLEMENTED` for a method your module does not export. See the
[module documentation](src/roadrunner_grpc_protobuf.erl) for them, and
Roadrunner's
[gRPC guide](https://github.com/arizona-framework/roadrunner/blob/main/docs/grpc.md)
for streaming, metadata, errors, deadlines, compression, health and
reflection. With `reflection => true`, `grpcurl -plaintext localhost:50051
list` lists the service.

## 🚧 Status

roadrunner_grpc_protobuf is in `0.x`. The core is functional and covered by tests,
but the API may change between minor versions. Pin an exact version
in your deps if you need stability across upgrades.

Contributions are welcome! Run `rebar3 precommit` before opening a pull request:
it checks formatting, runs xref, hank, dialyzer, and the docs build, and runs the
